## Design choices

| # | Step | Choice | Reason |
|---|------|--------|--------|
| D1 | 2 | Top frequent words exclude scikit-learn `ENGLISH_STOP_WORDS`, **except** negation words (no, not, nobody, never, nothing, none, nor, cannot, neither, nowhere), which are kept. | Negation words are known hypothesis-only cues for contradiction in SNLI; removing them would hide the effect being studied. |
| D2 | 2 | Top frequent words are computed on the SNLI **train** split, with lowercase and regex `\b\w+\b` tokenization. Hypothesis length = whitespace word count. | Train is the data the models learn from; simple, transparent tokenization. |
| D3 | 2 | Examples with label −1 (no annotator consensus) are dropped from all SNLI splits. | Specified in the project plan; these have no gold label. |
| D4 | 4 | The RandomForest trains on a stratified 100,000-example subsample of train (`train_test_split(train_size=100000, stratify=y, random_state=42)`; label counts 33,387 / 33,268 / 33,345). The same subsample is used for 5-fold CV. | Specified in the plan, to keep RF training feasible on a 16 GB / CPU-only machine. |
| D5 | 3 | The 3 overlap features in the full-input model are standardized with `StandardScaler`, fit on train only. | Puts the raw length difference on the same scale as the TF-IDF values for LogReg. |
| D6 | 3 | The overlap features use TF-IDF's default token pattern (`\b\w\w+\b`, lowercase), so single-character tokens like "a" are excluded. Length difference is in these tokens, not in whitespace words as in Step 2. Overlap counts are over word types (sets). | Overlap features see exactly the same words as the TF-IDF features. |
| D7 | 4 | `multi_class` isn't passed to LogisticRegression: it's deprecated in scikit-learn 1.9, and the default lbfgs solver is already multinomial for 3 classes. | Avoids a deprecation warning while matching the spec. |
| D8 | 5 | CV uses `Pipeline(TfidfVectorizer, model)`, so TF-IDF is refit on each fold's training part. CV std is the population std (numpy default, ddof=0). | No leakage across folds. |
| D9 | 5 | `train_time_sec` is wall-clock time (`time.perf_counter`) around `model.fit` only. It excludes feature extraction and prediction. | The paper reports training cost per model. |
| D10 | A1 | Learning-curve subsets use `train_test_split(train_size=n, stratify=y, random_state=seed)`. Seeds 42/43/44 for 1K, 5K and 10K; seed 42 only for 50K and 100K. The 100K/seed-42 subset is the same one used for the RandomForest and CV. TF-IDF is refit on each subset. std is the population std (ddof=0, as in D8). Per-seed results are in `learning_curve_runs.csv`. | Follows the A1 spec; ddof matches the earlier CV reporting. |
| D11 | A1/A2 | The full-training-set point (A1) and the (1,2) setting (A2) reuse the saved `models/hyp_tfidf.joblib` and `models/logreg_hyp.joblib` instead of refitting. Both reproduce `model_results.csv` exactly (0.6403 / 0.6398). | Identical settings and data, and the plan asks to reuse saved models. These rows have no `train_time_sec`. |
| D12 | A1 | The dummy line in Fig 6 is the saved full-train DummyClassifier's test accuracy (0.3428). | It's the same baseline as Fig 4. |
| D13 | B1 | MultiNLI transfer applies the saved SNLI-trained models and the saved train-fitted vectorizers/scaler unchanged (`features.transform_full` reuses the fitted full-input transformers). MNLI validation_matched and validation_mismatched contain no label −1 examples (0 dropped). | Matches the B1 spec: no refitting on MultiNLI. |
| D14 | B1 | The per-dataset dummy baseline is the saved SNLI-trained DummyClassifier applied unchanged, which always predicts entailment. Entailment is also the majority class of each MNLI split, so this equals a per-dataset majority baseline. | Consistent with "applied unchanged". |
| D15 | B2 | "Easy" and "hard" are defined by the saved hypothesis-only LogReg's predictions on SNLI test. The full-input LogReg includes its own hypothesis TF-IDF block, so the two models share inputs; the split is not independent of the full model's features. | Noted to support interpreting the easy/hard gap. |
| D16 | 7 | **Author decision: all explanation rankings are toward-class.** LR coef = `coef[c, j]`. NB = log P(j\|c) − log P(j\|not c). LR SHAP = sign(mean SHAP when the feature is present) × mean \|SHAP\|, using sign(coef) when the feature never appears in the sample. `shap_lr.csv` still stores mean \|SHAP\| per class as specified, plus mean-SHAP-when-present and the toward score. | Without this, comparing signed with unsigned scores would push Spearman ρ down partly as an artifact. |
| D17 | 7 | NB log-ratio is computed from the fitted `feature_count_` with the model's own smoothing (alpha = 1.0). "Not c" pools the other two classes' counts. NB was fit on TF-IDF values, so the counts are summed TF-IDF weights, not raw word counts. | Directly reflects the fitted NB model. |
| D18 | 7 | SHAP sample = `np.random.default_rng(42).choice(9824, 1000, replace=False)`, sorted (`explain.sample_idx`). Background = exact means of the full training feature matrix. LinearSHAP explains each class's linear score (log-odds space), not probabilities. | Fixed, reproducible sample; background from train only. |
| D19 | 7 | Also saved `results/top_words_shap_lr.csv` (top 20 per label by LR SHAP toward score). | It's the data behind Fig 10; no new analysis. |
| D20 | 7 | Agreement: per class, the union of the three methods' top-100 lists (219–237 features), then Spearman ρ between each pair of methods' scores over that union. The "MEAN over classes" rows and Fig 13 average ρ over the 3 classes. | Follows the spec, with 3 methods (P16). |
| D21 | 7 | Fig 12 and Step 8 rank "strongest shortcut words overall" by the max over classes of the LR SHAP toward score, unigrams only (no space in the feature name). Fig 11 uses SHAP's default beeswarm ordering (mean \|SHAP\|), so it also shows features that push *away* from contradiction (e.g. "people", "outside"). | One overall ranking shared by Fig 12 and Step 8. |
| D22 | 8 | Removal deletes whole-word, case-insensitive matches (regex `\b(word1\|word2…)\b`) from test hypotheses, then re-vectorizes with the saved vectorizer and scores with the saved LR (no retraining). This also removes bigram features that contain the word. Ranking (a) = unigrams by max over classes of the LR SHAP toward score from `shap_lr.csv` (pool: all 2,038 vocabulary unigrams). Ranking (b) = unigrams by max \|coef\| over classes, restricted to document frequency ≥ 0.1% of train (≥ 550 of 549,367; pool: 664 unigrams). Random control: 20 equal-count document-frequency bins over each ranking's pool; each shortcut word is replaced by a random word from the same bin, without replacement, excluding that ranking's top-100 words, falling back to the nearest bin with words left; seeds 42–46; std ddof=0. Per-seed random words are in `removal_random_runs.csv`. Both controls are now in `removal.csv`/`removal_random_runs.csv` with a `control_method` column: "nearest DF rank" (main, Fig 14; post-hoc, P23) and "bin-matched (20 DF bins)" (original, supplementary Fig 14b). | Follows the Step 8 spec plus the author's ranking (b). See P20 and P23 for matching quality. |
| D23 | 7 | RF Gini (`feature_importances_`, no class) is compared with each other method's class-averaged *magnitude*: mean \|coef\|, the class-mean of mean \|SHAP\|, and mean \|NB log-ratio\|. This is done over the union of all four top-100 lists (276 features), and the results are added as 3 rows labelled "class-averaged magnitude" in `agreement.csv`. Signed class averages aren't used because multinomial LR coefficients sum to ~0 across classes. | Author's request; Gini is unsigned. |
| D24 | 7 | Frequency check: per class, Spearman ρ between each method's toward-class score and the feature's train document frequency (number of train hypotheses containing it), over the same per-class union of top-100 features used in the agreement analysis. | Tests the frequency explanation of the agreement results on the same feature set. |
| D25 | 7 | Length check: top 10 features by the overall LR SHAP score (D21; unigrams and bigrams), Spearman ρ between each feature's per-example **neutral**-class SHAP value and hypothesis length (whitespace words, as in Step 2) on the same 1,000-example sample. | Author's spec. |
| D26 | 9 | Error examples: confidence = max class probability. Groups A and B require hypothesis-only confidence > 0.9; group C has no confidence threshold. 5 examples are drawn at random per group with `default_rng(42)` (pool sizes 827 / 73 / 1,121). Top 3 SHAP = the 3 present features with the highest LinearSHAP value for the hypothesis-only model's *predicted* label. | Random rather than most-extreme examples, so they aren't cherry-picked. |
